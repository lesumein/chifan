# 치판 吃饭

중국 배달앱(메이퇀 등)을 쓰는 한국인을 위한 폰 웹앱.
**카테고리와 그림으로 메뉴를 고르면 중국어 검색어를 복사**하고, 배달앱(지금은 웹페이지)을 열어 준다.
사용자는 앱 검색창에 붙여넣기만 하면 된다.

> 치판은 메이퇀 등 배달앱과 관계없는 개인 실험 도구다. 검색어만 만들어 줄 뿐, 배달앱 화면·데이터에 접근하지 않는다.

![Pixel 7 화면](screenshots/pixel7-01-home.png)

## 실험 목적

타오바오 Search Translator(영어 검색어 → 중국어 검색)처럼, 중국어를 못 읽는 사람이
**"메뉴 이름을 몰라서 검색을 못 하는"** 문제를 검색어 복사만으로 풀 수 있는지 확인한다.

- 확인할 것: 카드 → 복사 → 앱 열기 → 붙여넣기 흐름이 실제 폰에서 불편 없이 되는가
- 확인할 것: 사전의 중국어 표기로 검색했을 때 원하는 가게·메뉴가 실제로 나오는가
- 확인할 것: 중국 안(VPN 없이)에서 github.io로 열리고, 한 번 연 뒤 오프라인에서도 쓸 수 있는가

## 첫 버전 범위

| 기능 | 내용 |
|---|---|
| 앱 설치 안내 | 첫 화면 위 카드: **[앱 설치하기]** → 스토어 열기 + `美团` 복사(스토어 검색창에 붙여넣기용). **[이미 있어요]**로 숨김. 정보(ⓘ)에도 설치 버튼 |
| 메뉴 고르기 | 카테고리 10개 탭 → 카드 그리드. 카드에 중국어(크게)·병음·한국어 이름·한 줄 설명·맵기 |
| 검색어 복사 | 카드를 누르면 중국어 검색어 자동 복사 + “복사됨: 麻辣烫” 토스트. 하단 바에 마지막 검색어 표시 |
| 앱 열기 | 하단 **[앱으로 열기]** / **[웹]** 두 버튼, 사용자가 고른다. 누를 때만 연다. 앱은 폰 종류를 자동 인식해 시도하고 안 열리면 웹으로(아래 참고) |
| 한국어 검색 | 이름·별칭 부분 일치, 초성(`ㅁㄹㅌ`, `ㅉㅈㅁ`), 입력 중인 글자(`말` → 마라탕), 중국어·병음(`mala`)도 됨 |
| 중국어 읽기 | 메이퇀에서 복사한 메뉴·옵션 글을 붙여넣으면 아는 단어마다 한국어 뜻을 달아 줌(가장 긴 단어부터 맞춤, 메뉴 이름은 눌러서 상세). 옵션·맛·음료·재료·주문·배달·가게 등 단어장 약 14,200개(그중 한 글자 항목 약 8,000개), 한국어로도 찾기 |
| 요청사항 문구 | 35개 문구를 골라 중국어 주문 메모(`少辣，不要香菜，不需要餐具…`)로 복사. 서로 겹치는 것(맵기, 얼음 등)은 하나만 |
| 내 사진 | 카드의 📷 → 상세 화면에서 사진 찍기/앨범에서 고르기. **이 기기 IndexedDB에만** 저장(긴 변 720px JPEG로 줄여서) |
| 최근 | 복사한 메뉴가 ‘최근’ 탭에 쌓임(localStorage) |
| 오프라인 | 서비스워커가 모든 파일을 캐시. 홈 화면에 추가 가능(PWA) |
| 인앱 브라우저 | 카카오톡·위챗 등 앱 안 브라우저면 “외부 브라우저로 열기” 안내 + 주소 복사 버튼 |

### 지키는 원칙 (lab 공통 원칙)

- 폰(안드로이드) 우선, 서버 없음, 저장은 기기 안에서만(localStorage / IndexedDB)
- 다른 서비스의 코드·문장·그림·데이터를 쓰지 않음. 설명 문구는 직접 썼고, 그림은 이모지 + 직접 그린 SVG(아이콘, 무늬)
- 웹에서 가져온 사진(위키미디어 포함) 없음
- 구글 폰트·외부 CDN·구글 API 없음. 모든 파일 자체 포함 (`tests/check-data.js`가 외부 주소를 검사)
- 메이퇀 페이지는 건드리지 않음: 프록시·iframe·비공식 API·스크래핑·차단 우회 없음. 서비스워커도 다른 출처 요청은 건드리지 않음
- 상표: 앱 이름·아이콘에 메이퇀 이름/로고/색을 쓰지 않음. “메이퇀에서 열기” 같은 설명 문구만 사용

## 앱 열기 방식과 확인 상태

앱 여는 주소는 **`js/config.js` 한 곳**에만 있다.

1. 카드를 누르면 검색어가 클립보드에 복사된다. (검색어를 앱에 직접 넘기는 딥링크 형식은 공개돼 있지 않아서 클립보드가 기본)
2. 하단 바에서 사용자가 고른다.
   - **[웹]**: H5 `https://h5.waimai.meituan.com/waimai/mindex/home` 를 새 탭으로 연다.
   - **[앱으로 열기]**: 폰 종류를 User-Agent로 자동 인식한다.
     안드로이드는 `intent://<path>#Intent;scheme=<scheme>;package=<package>;S.browser_fallback_url=<H5>;end`,
     iOS는 URL 스킴을 시도하고 `fallbackMs`(1.6초) 안에 페이지가 숨겨지지 않으면 H5로 넘어간다.
     PC나 앱 안 브라우저(카톡·위챗 등)에서는 이 버튼을 숨긴다.
   - 웹 페이지는 앱이 **설치돼 있는지 알 수 없다.** 그래서 자동으로 고르지 않고 두 버튼을 둔다.
   - `appOpen.enabled: false`로 두면 [앱으로 열기]를 숨긴다(웹만).
3. 사용자가 앱 검색창을 길게 눌러 붙여넣기.

페이지가 열리자마자 앱으로 넘기는 동작은 없다(브라우저가 막거나 확인창을 띄우므로). 모든 이동은 사용자 탭에서만.

설치 링크가 틀려도 `美团`이 복사돼 있으니 스토어 검색창에 붙여넣으면 된다. Google Play는 중국 안에서 안 열리고, 중국 폰(샤오미·화웨이 등)은 `market://`을 자기 스토어로 연다.

**2026-10-28 실기기 확인 (안드로이드):** [앱 설치하기] → 설치됨, [앱으로 열기] → 메이퇀 앱 실행됨. 앱 첫 화면만 열 때는 검색어가 안 들어감.
공개된 URL 스킴 모음에 나온 후보를 `lab.html`로 하나씩 시험한 결과, 메이퇀 앱 `search?q=` 형식만 검색 결과를 열었다
(`meituanwaimai://…/search?query=`, `query=`, `keyword=`, `mtwm://`는 안 됨). [앱으로 열기]는 마지막으로 복사한 검색어를 이 형식으로 넘긴다.
안 되더라도 앱은 열리고 검색어는 클립보드에 있으므로 붙여넣기로 이어진다. (메이퇀 페이지나 앱 코드는 분석하지 않음)

**검색 링크 시험 페이지:** `lab.html` (https://lesumein.github.io/chifan/lab.html). 공개 URL 스킴 모음에 나온 후보
(`meituanwaimai://waimai.meituan.com/search?query=` 등)를 폰에서 한 번씩 눌러 보는 페이지. 되는 형식이 나오면 `js/config.js`에 반영한다.

실제 폰에서 확인되면 `js/config.js` 값을 고치고 `enabled: true`로 바꾼 뒤, 이 표에 날짜와 기기를 적는다.
(메이퇀 페이지나 앱 코드를 분석해서 알아내지 않는다. 폰에서 직접 확인한다.)

- `data/t2s.json` — 번체·이체자 → 간체 약 2,800자 (Unihan kSimplifiedVariant, 표준 간체는 건드리지 않음)
- `data/hanja.json` — 한자 → 한국어 음 10,066자 (유니코드 Unihan 기반, `data/hanja.LICENSE.txt`)

`foods.json` 항목:

```json
{"id": "malatang", "cat": "soup", "ko": "마라탕", "aka": ["마라탄"],
 "zh": "麻辣烫", "py": "málàtàng", "desc": "한 줄 설명", "spicy": 2, "emoji": "🍲",
 "q": "(선택) 복사할 검색어가 zh와 다를 때", "check": true, "img": true}
```

- `spicy`: 0 안 매움 ~ 3 아주 매움
- `check: true`: 중국어 표기 **검증 필요** (카드에 ‘확인 중’ 표시)
- `img: true`: `img/<id>.jpg`가 있을 때만 (직접 찍은 사진 자리, `img/README.md` 참고)
- 항목을 늘린 뒤 `node tests/check-data.js`로 검사 (id 중복, 빠진 칸, zh 중복, 외부 주소 등)

## 안드로이드 앱: 한국어 덧그리기 + 떠다니는 버튼 (실험)

웹앱은 메이퇀 화면 안에서는 아무것도 못 한다(글자 복사도 막혀 있음). 그래서 다른 앱 **위에** 한국어를 그려 주는 안드로이드 앱을 `android/`에 따로 만들었다.
lab 원칙 중 "웹앱 우선"에서는 벗어나지만, 나머지(안드로이드 폰 우선·서버 없음·기기 저장·메이퇀 안 건드림)는 그대로다.

**방식: 화면 캡처 + 폰 안 OCR.** 처음(0.1)에는 접근성 서비스로 글자를 읽었는데, 스토어 밖에서 받은 접근성 앱은 Google Play 프로텍트가 설치 자체를 막았다
("기기 보호를 위해 앱 차단됨", 무시하고 설치 버튼 없음 — 2026-10-29 실기기). 그래서 0.2부터 접근성을 완전히 빼고,
사용자가 허용한 화면 캡처(MediaProjection)를 폰 안 OCR(ML Kit 중국어 인식, 모델 내장)로 읽는다. 덕분에 메이퇀뿐 아니라 **어떤 앱이든** 한자가 보이면 동작한다.

### 지금 상태 (0.29)

| 항목 | 상태 |
|---|---|
| 설치 파일 | 릴리즈 서명 `apk/chifan-0.29-release.apk`(33MB), 압축본 `apk/chifan-0.29-release.zip`(16MB) |
| 사전 | 단어장 약 14,200개 + 글자 뜻·발음·번체 표 |
| 엄격 번역율 | 처음 보는 메뉴 이름(봉인 세트)에서 99.3~99.5% (0.29부터 잡음 차단으로 일부러 덮지 않는 줄 포함). 사전 항목과 규칙만으로 모든 한자를 읽은 줄의 비율 |
| 의미 정확도 | 무작위 100줄씩 사람(개발 중 직접) 판정 약 84~90%. 틀리는 것은 대부분 가게마다 새로 나오는 고유 이름·음역어 |
| 폰 실기 확인 | 2026-10-30 0.28 폰 화면 2장 확인: 라벨이 대체로 붙음. 잡음 라벨(사진 속 글씨·잘린 줄), OCR 오독(月售→月昔), 원문 비침을 0.29에서 고침 |

**번역율과 정확도는 다른 숫자다.** 번역율은 "사전으로 다 읽었다", 정확도는 "뜻이 맞다". 목표였던 "실제 앱 사용에서 99.9%"는 폰 ML Kit가 읽은 줄로 재야 하므로 아직 측정되지 않았다. 폰에서 치판 창의 **[OCR 결과 복사(JSON)]**와 스크린샷을 모으면 그 줄로 다시 잰다.

**하는 것**
- 0.6초에 한 번, 화면이 바뀌었을 때만 캡처해 OCR → 줄마다 라벨을 **조각 사전**으로 만든다 (`Labeler.kt`, 사전은 `Lexicon.kt`).
  지금 방식(0.27~): 번체를 간체로 바꾼 뒤, 줄 전체에서 **가장 비용이 낮은 분절**을 고른다(숫자 규칙 0.5, 여러 글자 말 1, 한 글자 말 1~1.6, 음역어 2, 글자 뜻 2.5, 드문 글자 발음 3, 못 읽음 5). 단어로 다 읽히면 그 라벨, 아니면 빈 글자를 글자 뜻으로 채운 라벨(회색 띠 = 직역). 리뷰처럼 긴 문장은 번역 모델이 있으면 기계 번역을 먼저.
  아래 설명 중 0.26 이전 것은 그때의 방식이고, 버전별 바뀐 점은 아래 기록에 있다.
  중국 메뉴 이름은 재료·조리법·형태의 조합이라 문장 번역보다 조각이 잘 맞는다: `回锅肉盖饭` → 회과육 · 덮밥, `重庆小面单人餐` → 충칭 · 샤오미엔 · 1인 세트.
  순서: 숫자 규칙 36개(`4.9折` → -51%, `满30减5` → 30↑ -5, `约35分钟` → 약 35분, `起送¥20` → 최소 ¥20, `4.8分` → 4.8점…) → 사전 가장 긴 말부터. 가격·시간·숫자는 그대로 남긴다. `【】|/` 는 조각 경계. 단어장의 `short`(짧은 표기: 微辣 → 약간, 选规格 → 옵션)가 있으면 라벨엔 그것을 쓴다.
  덮어쓰기 라벨은 2자 이상 사전 조각이나 규칙이 하나는 있어야 붙고, **한자음은 넣지 않는다**(0.13: 잘못 읽힌 글자·사진 속 글씨의 한자음이 전부 소음이 됐다. 한자음은 '읽은 글자' 탭에서만). 가격(¥12)이 섞인 줄은 덮지 않는다.
  **빨강** = 사전, **갈색** = 메뉴 이름 포함, **파랑** = 기계 번역(켠 경우만).
- 한자음 표 `data/hanja.json`(10,066자)은 유니코드 Unihan에서 만든 것 (`data/hanja.LICENSE.txt`). 회과육·마파두부·탕수육처럼 한국식 중국 음식 이름은 대개 한자음이라 꽤 알아볼 수 있다.
- 기계 번역(ML Kit, 중→영→한)은 0.5~0.10에서 모든 줄에 기본이었으나 `回锅肉盖饭` → "Q 냄비로 돌아 가가 고기 쌀" 수준이라 0.11부터 꺼 두었다. **0.21부터 다시 기본 켜짐**, 단 사전이 한자 60%(문장 75%)를 못 읽은 줄에만 — 메뉴 이름은 사전이, 리뷰·안내문은 번역기가 맡는다. 가격 줄·지점 이름처럼 '읽었지만 덮을 게 없는' 줄엔 끼어들지 않는다(`Result.known`).
- **0.22:** 기계 번역은 **문장처럼 생긴 줄**(한자 10자 이상이거나 문장 부호가 있는 줄)에만. 짧은 제목(菌锅米线)에 번역기를 쓰면 "냄비 냄비 线" 같은 게 나와 원문보다 나쁘다 — 모르는 짧은 줄은 원문 그대로 둔다. 한자가 남은 번역 결과도 버린다. 같은 자리에서 글자가 달라지면 상자도 새 것으로(옛 좁은 상자에 긴 라벨을 넣어 …로 잘리던 문제).
- **0.29 (폰 화면 2장 반영):** 잡음 차단 — 두 글자 이상 말·숫자 규칙이 없고 일반 한 글자·직역이 70%를 넘는 줄은 덮지 않는다(사진 속 글씨·잘린 줄이 "막 · 찾은 · 지난…"이 되던 것). 폰 OCR 오독 보정(月昔→月售, 选本格→选规格). 本店必点·多人分享·中国首创·无骨·双拼 등 화면 표현과 메뉴 이름 약 170개. 라벨 바탕을 더 어둡게, 글자에 그림자 — 안드로이드가 통과형 오버레이를 80% 불투명까지만 허용해 밑 글자가 비치기 때문.
- **릴리즈 빌드 (0.28부터):** `apk/chifan-0.29-release.apk`(서명됨)와 압축본 `apk/chifan-0.29-release.zip`. 개인 배포용 서명 키는 레포에 두지 않는다 (`android/keystore/`, `android/keystore.properties`는 .gitignore). 이전 디버그 버전과 서명이 달라 한 번은 지우고 설치해야 한다. 빌드: `android/keystore.properties`에 storeFile·storePassword·keyAlias·keyPassword를 두고 `cd android && ./gradlew assembleRelease` (없으면 서명 없이 빌드됨). 릴리즈 빌드에선 lint 다운로드를 생략한다.
- **0.28:** 중국 지급시·유명 현·관광지 약 450곳(한국어 표기는 중국어 발음 표기 원칙, 金华 → 진화), 메뉴용 덕담·사자성어와 약재·약초 약 80개, 酱은 '장·소스'로(巧克力酱 → 초콜릿 소스, 桃酱 → 복숭아잼). 새 봉인 세트(23~24쪽 1,263줄) 엄격 번역율 99.84%, 무작위 100줄 사람 판정 의미 정확도 약 85%.
- **0.27 — 분절을 동적 계획법으로:** 앞에서부터 가장 긴 말을 잡던 방식을 줄 전체 최소 비용 분절로 바꿨다 (규칙 0.5, 여러 글자 말 1, 한 글자 말 1/1.6, 음역 2, 글자 뜻 2.5, 드문 글자 발음 3, 못 읽음 5; 같은 비용이면 앞쪽 말을 길게). 咖喱鸡肉 "카레 닭 · 고기" → "카레 · 닭고기", 意大利面包 "파스타 · 찐빵" → "이탈리아 · 빵". 26,000여 줄에서 바뀐 45줄을 모두 읽어 확인. `N两` → N량(N×50g), `N斤` → N근.
  새 봉인 세트(레시피 21~22쪽 1,355줄) 엄격 번역율 99.93%. 무작위 100줄 사람 판정 의미 정확도 약 84% — 틀린 것은 한 글자씩 풀면 안 되는 말(口水·足球·止泻), 지명(金华), 분절(肉丝娃娃菜). 보인 것은 고쳤다. **번역율(사전으로 다 읽음)과 의미 정확도는 다르다.** 의미 정확도 99.9%는 메뉴마다 새 고유 이름이 나오는 한 사전 방식으로는 도달하지 못하고, 실제 앱 환경(폰 ML Kit OCR) 검증은 폰에서 뽑은 OCR 결과가 있어야 한다.
- **0.26 — 엄격한 번역율 99.9%:** "번역됨"을 **사전 항목(단어·한 글자 형태소)과 규칙만으로 한자를 전부 읽은 줄**로 엄격하게 다시 정의했다 — 글자 뜻 직역(`zi.json`)·중국어 발음 표기가 한 글자라도 쓰이면 실패. 0.25의 "라벨 있음 100%"는 직역을 포함한 느슨한 숫자였고, 엄격 기준으로는 처음 보는 메뉴 이름 57%였다.
  - 사전 약 13,600항목: 메뉴 학습 말뭉치(레시피 사이트 1~14쪽, 약 1만 5천 줄)의 빈 구간을 빈도순으로 채우고, **중국 표준 간체(通用规范汉字表) 8,105자 전부**를 메뉴 문맥 뜻의 한 글자 항목으로(직접 작성, 영문 정의 참고), 세계 나라·도시·서양 요리·치즈·외식 브랜드의 정해진 한국어 표기 약 440개.
  - 한자 숫자 → 아라비아 숫자(三十六 → 36, 단 二十四节气 같은 사전 말 우선), 거리 `N米` → `Nm`, 음역 판정 글자에서 뜻이 분명한 음식 글자(汤·梅·乌…) 제외, 이체자(醸·徳·糉) 간체화.
  - **측정 (봉인한 세트, 고칠 때 보지 않음):** 레시피 15~16쪽 1,469줄 99.86%, 17~20쪽 2,767줄 99.93% (합계 99.91%). 받은 메이퇀 화면 OCR 456줄 100%. 이 중 여러 글자 단어만으로 읽힌 줄은 약 63%(화면은 77~97%), 나머지는 한 글자 형태소가 섞인다.
  - **정확도 (사람 판정):** 봉인 세트에서 무작위 60줄씩 두 번 직접 읽어 보니 약 88~90%가 뜻이 맞거나 이해 가능, 나머지는 음역어를 뜻으로 풀거나(沙布蕾 → 모래·천) 분절이 틀린 경우(炒米粉 → 볶은 쌀). 보인 것은 고쳤다. 번역율과 정확도는 다른 숫자다.
  - 파이썬 시뮬레이터와 Kotlin 라벨러 24,778줄 대조 차이 0 (`LabelerParityTest`). 폰 실기에서는 아직 확인하지 못했다.
- **0.25 — 번역율 99.9%+:** 라벨러를 2단계로. ① 단어(사전 약 4,100개 + 숫자 규칙) ② 단어로 다 못 읽은 줄은 빈 글자를 **글자 뜻 표**(`data/zi.json`, 약 3,100자, 직접 작성)로 채운다. 소리만 빌린 글자·음역어(慕斯, 洪都拉斯)는 **중국어 발음 한글 표기**(`data/sound.json`, Unihan kMandarin → 국립국어원 중국어 표기 규칙), 뜻 표에 없는 드문 글자는 한국 한자음. 번체는 먼저 간체로(`data/t2s.json`, Unihan, 표준 간체는 건드리지 않음). 글자 뜻이 절반 넘게 섞인 라벨은 **회색 띠 = 직역**. 긴 문장(리뷰)은 기계 번역 모델이 있으면 그쪽을 먼저, 없으면 단어 풀이.
  측정(`tests/sim/coverage.py`, 고칠 때 한 번도 보지 않은 말뭉치): 레시피 이름 2,640줄 100%(직역 10%), 위키 요리 목록 820줄 100%(직역 47%: 외국 음식·지명), 받은 메이퇀 화면 OCR 456줄 100%, 웹 화면 OCR 1,731줄 100%. 말뭉치는 다른 서비스의 글이라 레포에 넣지 않는다.

- **0.24 — 깜빡임:** 작은 화면 변화(썸네일 로딩, **1초마다 바뀌는 카운트다운**, 움직이는 배너)에 라벨을 더 이상 숨기지 않는다. 라벨을 띄운 채 읽고, 라벨 아래 줄은 버리고(우리 한국어를 다시 읽지 않게) 기존 라벨은 유지한다. 0.17~0.23은 라벨을 한 프레임 숨겨 읽어서 카운트다운이 있는 화면에선 1초마다 라벨이 꺼졌다 켜졌다. 결과가 같으면 다시 읽는 간격을 0.2초 → 최대 6초로 늘린다 (`FrameGateTest`: 40초 카운트다운 동안 지우기 0번).
  두 줄로 합친 문단이 사전에서 떨어지면 줄마다 따로 읽는다. 기계 번역은 문장 부호가 있거나 한자 16자 이상인 줄에만(메뉴 제목 제외). 넓히기는 먼저 그린 라벨도 장애물로 보고, 왼쪽은 24dp까지만. 스테이크·양식 분야와 판촉 문구 약 100개.
- **0.23 — 웹에서 실제 메뉴 이름으로 측정:** 공개 레시피 사이트의 요리 이름(학습용 179개, 처음 보는 검증용 196개·312개)으로 사전 커버리지를 재며 고쳤다. 검증용 56% → 84%·92%. 고친 것은 화면별 단어가 아니라 규칙과 분류:
  - 조리 동사·모양·기본 음식 한 글자(炒蒸炖煎烧拌… 丁丝片块… 饭面粥汤饼… 鸡鸭鱼虾肉蛋 小大酱)는 단어 안에서도 읽는다 (`BOUND`). 'A炒B', '酸菜鸡' 같은 조합이 메뉴의 대부분이다.
  - 가장 긴 말이 뒤를 깨뜨리면 한 글자 짧게 잘라 본다 (家常菜谱 → 家常+菜谱).
  - 한자 8자 이하 이름은 50%만 읽어도 덮되, **끝 글자(음식 본체)를 읽었을 때만** — 湖南糖粑 → "후난" 같은 오해 방지.
  - 좁은 칸: 넓히기는 오른쪽 다음 글자까지 → 왼쪽(줄 높이 3배까지, OCR은 사진을 모른다) → "쓰촨 · 간식"을 "쓰촨·간식"으로 → 글자 줄이기 → … 순. 원문이 아주 작으면 최소 글자 크기도 줄 높이 안으로.
  - 성·도시·요리 계통 약칭(苏菜·浙菜…)·약재·디저트·면·떡류 등 분류 추가. 단어장 약 2,650개.
- 단어장은 0.21에서 약 1,000개 → 2,100개 (재료·조리법·지역 요리·음료·옵션·앱 화면·리뷰 문구를 분류별로 한꺼번에). 메뉴 이름은 재료·조리법·형태의 조합이라 어휘가 유한하다 — 화면마다 단어를 보태는 게 아니라 분류를 채우는 식으로 늘린다. 사용자 키가 필요한 온라인 번역 API는 일반 사용자가 못 쓰므로 넣지 않는다.
- 오른쪽의 **떠다니는 치판 버튼**: 메뉴 고르기(검색어 복사)·요청사항(메모 복사)·단어장. 위아래로 끌어 옮김. 창이 열려 있는 동안은 캡처를 쉰다.
- 라벨은 창 안 스위치나 설정 화면에서 끌 수 있다.
- 창의 **'읽은 글자'** 탭: 직전 화면에서 OCR이 읽은 줄과 붙인 뜻('—'는 사전에 없음). [전부 복사]해서 보내면 사전에 넣는다. **[OCR 결과 복사(JSON)]**는 글자+상자 원본 — `tests/sim/render.py`에 넣으면 폰 화면을 그대로 재현해 규칙을 고칠 수 있다.
- 라벨은 기본적으로 **원래 글자 위에 덮어** 그 자리를 한국어로 바꿔 보인다(0.12). 글자 높이에 맞춰 크기를 정하고, 폭에 안 들어가면 먼저 같은 줄의 다음 글자 직전까지 넓히고, 그래도 안 되면 글자를 줄이고(최소 8dp), 그래도 안 되면 …로 자른다(0.17: 넓히기를 줄이기보다 먼저 — 글자가 작아지던 원인). 이미 덮은 상자와 30% 넘게 겹치면 건너뛴다. 종류는 왼쪽 색 띠(빨강 사전·갈색 메뉴·회색 한자음·파랑 번역). 설정에서 끄면 글자 옆에 작은 라벨(오른쪽 → 아래 → 위).
- 되먹임 방지(0.9): 캡처는 라벨을 한 프레임 숨긴 깨끗한 화면으로만 한다. 라벨을 그린 직후 프레임은 비교 기준으로만 쓰고, 읽은 글자·자리가 지난번과 같으면 라벨을 다시 그리지 않는다. 0.3~0.8은 자기 라벨을 다시 읽어 라벨이 계속 바뀌었다.
- 라벨 추적(0.10): OCR은 같은 화면도 상자가 매번 몇 px씩 달라서, 같은 글자가 거의 같은 자리면 기존 라벨을 자리째 유지한다. 화면 비교는 상태바를 뺀 밝기 격자로 하고 0.6% 미만 변화(커서·아이콘 깜빡임)는 무시.
- **멈춘 화면만 읽는다(0.14):** 캡처→인식→그리기에 0.3~0.6초가 걸려 스크롤 중에 읽으면 라벨이 예전 자리에 찍힌다. 화면이 바뀌기 시작하면 라벨을 바로 지우고, 프레임이 더 안 들어온 지 200ms가 지나야 읽는다(오버레이 구석 1px을 토글해 프레임을 하나 받아 OCR). 읽는 사이 다시 움직이면 그 결과는 버린다. 틀린 자리의 라벨보다 잠깐 없는 게 낫다.
  **작은 변화(0.17):** 기준과 0.6~12%만 다르면(0.18: 30%→12%, 오른쪽 목록만 스크롤돼도 지우도록)(썸네일 로딩, 작은 애니메이션) 라벨을 지우지 않고, 멈춘 뒤 라벨을 한 프레임만 숨겨 읽고 바로 되살린다. 결과가 같으면 라벨을 건드리지 않는다 — 메뉴 화면이 처음 뜰 때 썸네일이 하나씩 로딩되며 라벨이 깜빡이던 원인. 12% 넘게 바뀌면(스크롤·화면 전환) 즉시 지운다.
- OCR이 같은 높이의 글자를 한 줄로 합쳐 읽는 것(왼쪽 분류 + 오른쪽 제목)은 단어 간격이 줄 높이의 1.2배를 넘으면 가른다(0.18). 같은 자리에서 읽을 때마다 글자가 조금씩 다르게 나오면 더 긴 쪽을 유지한다.
- **덮을지 말지(0.20):** 사전·규칙이 읽은 한자가 줄의 한자 60%(12자 넘는 문장은 75%) 이상일 때만 덮는다. 0.19까지는 조각 하나만 있어도 덮어서, 리뷰·안내문 위에 "4 · 상세 · 가게" 같은 조각이 원문을 가렸다. 모르는 문장은 그대로 두는 게 낫다 (읽은 글자 탭엔 남는다). 가격으로 시작하는 줄(¥1.79 6折 ¥3)도 덮지 않는다. 지점 이름(鲜鱼口店)은 뜻 없이 '읽은 것'으로만 친다.
- **라벨 색(0.20):** 어두운 바탕에 흰 글자. 폰에서 오버레이 창이 반투명으로 보이는 경우가 있어(터치를 통과시키려고 80%로 깔리는 기종) 밝은 바탕은 밑의 중국어와 겹쳐 둘 다 못 읽었다.
- **두 줄로 접힌 이름(0.19→0.20):** 왼쪽 분류 "春龙抬首鸿 / 运当头"처럼 줄바꿈된 이름은 줄마다 따로 읽으면 어느 쪽도 사전에 안 맞는다. 같은 열(가로 겹침 60% 이상)에서 바로 아래(간격이 줄 높이의 0.8배 이내)에 있고 글자 높이가 비슷(30% 이내)하며 **사전의 말이 줄 경계에 걸쳐 있는**(鸿|运当头 의 鸿运) 줄만 한 문단으로 합쳐 읽는다 — 0.19는 모양만 보고 합쳐서 제목 + 지점 이름(锦芳小吃|艾窝窝 / 鲜鱼口店)까지 한 덩이로 덮었다. 라벨은 " · " 조각(모자라면 띄어쓰기) 단위로 줄 수만큼 나눠 덮고, 나눌 수 없으면 윗줄만 덮는다(`Paragraphs.kt`, `ParagraphsTest`; 시뮬레이터 `tests/sim/paragraph.py`와 같은 규칙). 괄호뿐인 뜻("(메이퇀)" 워터마크)은 덮지 않는다. 좁은 칸에 안 들어가는 "월 0 판매"는 띄어쓰기를 빼서("월0판매") 넣는다.
  이 상태 기계는 `FrameGate.kt`(안드로이드 의존 없음)로 떼어 두고 `FrameGateTest`에서 가짜 시계로 8가지 시나리오(정지, 스크롤, 읽는 도중 재스크롤, 깜빡임, 프레임 미수신, 자기 그림, 작은 변화, 작은→큰 변화)를 돌린다: `cd android && ./gradlew testDebugUnitTest`.
- 라벨 규칙: 줄 전체 일치 > 단어 일치 > 줄 안에서 찾은 말 이어 붙이기. 이어 붙일 땐 한 글자 매칭(甜·冰·热…)은 버리고, 찾은 말이 한자의 절반을 못 덮으면 안 붙인다.

**안 하는 것 (설계로 막아 둠)**
- 다른 앱 화면을 누르거나 입력·스크롤하지 않는다. 접근성 권한을 쓰지 않으므로 할 수도 없다.
- 읽은 화면·글자를 기기 밖으로 보내지 않는다. 글자 인식도 번역도 폰 안에서 돈다. 인터넷 권한은 0.5부터 있지만 **번역 모델을 내려받는 데만** 쓴다 — 코드에 화면 내용을 보내는 곳이 없고, 열린 소스라 확인할 수 있다.
  (0.2~0.4는 인터넷 권한이 아예 없었다. 번역을 기본으로 넣기로 하면서 되돌렸다. 중국 번역 서비스(바이두 등)는 화면 글자를 서버로 보내야 해서 쓰지 않는다.)
- 캡처한 화면을 저장하지 않는다. 글자를 읽은 뒤 바로 버린다.
- 메이퇀 앱·서버에 접근하지 않는다.

**빌드:** JDK 17+, Android SDK(platform 35, build-tools 35). `android/local.properties`에 `sdk.dir=...` 넣고
- 릴리즈: `android/keystore.properties`(storeFile·storePassword·keyAlias·keyPassword, 커밋 안 함)를 두고 `cd android && ./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`. 키가 없으면 서명 없이 빌드된다.
- 디버그: `./gradlew assembleDebug`.
- 테스트: `./gradlew testDebugUnitTest` — `FrameGateTest`(스크롤·깜빡임 상태 기계), `ParagraphsTest`(접힌 줄), `LabelerParityTest`(Kotlin 라벨러 = 파이썬 시뮬레이터; `CHIFAN_PARITY=표.tsv`를 주면 그 말뭉치 전체를 대조).
외부 라이브러리는 ML Kit 둘: OCR(`text-recognition-chinese`, 모델 내장)과 번역(`translate`, 모델은 내려받음). arm64 폰만 지원(용량 때문, 2017년 이후 폰은 다 arm64).
사전은 `app/build.gradle.kts`에서 레포의 `data/`를 assets로 바로 쓴다.
0.28부터 릴리즈 서명. 서명 키는 레포에 없으므로, 키를 잃으면 다음 버전은 한 번 지우고 설치해야 한다.

**2026-10-29 실기기 확인 (안드로이드, 0.2):** 메이퇀 美食 목록 화면에서 OCR 덧그리기 동작, 라벨 위치 맞음. 사전에 가게 종류·앱 화면 단어가 없어 빈 곳이 많았고 한 글자 매칭이 엉뚱한 라벨(甜→단, 冰→차갑게)을 만들어 0.3에서 단어장 250개 추가 + 매칭 규칙 수정.

**아직 모르는 것 (실기기 확인 필요)**
- 가게 메뉴·옵션 화면(배달 주문 흐름)에서 OCR 정확도.
- 배터리·발열: 화면이 바뀔 때만 돌리지만 스크롤 중에는 계속 돈다.
- 메이퇀이 캡처를 막는 화면(결제 등)이 있는지 — 그 화면은 검게 잡혀 라벨이 안 붙는다.

**왜 '앱 안에서 바로 주문'은 안 하나:** 메이퇀에 소비자용 주문 API가 없다. 가능한 길(비공식 API 흉내, 메이퇀 웹에 끼워 넣기)은 모두 처음에 뺀 것들이다.

## 파일 구조

```
index.html              화면 (빌드 없음)
css/style.css           스타일 (시스템 글꼴만)
js/config.js            앱 여는 주소 (여기 한 곳만)
js/open.js              앱/H5 열기, 인앱 브라우저 감지
js/hangul.js            초성·부분 일치 검색
js/photos.js            내 사진 IndexedDB 저장
js/app.js               화면 로직
data/*.json             사전
img/                    직접 찍은 사진 자리 (img/<id>.jpg)
icons/                  직접 그린 아이콘·무늬 SVG + PNG
sw.js                   오프라인 캐시 (파일을 바꾸면 VERSION 올리기)
manifest.webmanifest    홈 화면 추가
tests/                  데이터 검사, 폰 화면 테스트, 아이콘 생성
tests/sim/              안드로이드 라벨러의 파이썬 판(시뮬레이터)·렌더러·번역율 측정·Kotlin 대조표
android/                안드로이드 덧그리기 앱 (Kotlin + ML Kit OCR)
apk/                    빌드한 설치 파일 (릴리즈 APK + zip)
screenshots/            테스트가 만든 스크린샷
```

## 로컬 실행·테스트

```sh
python3 -m http.server 8000          # http://localhost:8000
node tests/check-data.js             # 사전·외부 주소 검사
node tests/screens.js                # Playwright: Pixel 7 / iPhone 13 화면 테스트 → screenshots/
node tests/make-icons.js             # icons/*.svg → PNG
python3 tests/sim/render.py shot.jpg shot.ocr.json out.png   # 안드로이드 덧그리기 모양을 폰 없이 확인 (tests/sim/README.md)
python3 tests/sim/coverage.py 말뭉치.txt [화면.ocr.json]       # 번역율: 엄격(사전 항목만) / 단어만 / 라벨 있음
python3 tests/sim/parity.py 말뭉치.txt > /tmp/p.tsv && (cd android && CHIFAN_PARITY=/tmp/p.tsv ./gradlew testDebugUnitTest)   # Kotlin = 파이썬 대조
node tests/sim/shoot.js /tmp/fx && python3 tests/sim/batch.py /tmp/fx /tmp/fxout   # 가짜 배달앱 화면 7종을 한꺼번에
```

`tests/screens.js`는 복사(클립보드 값), 토스트, 로드 시 자동 이동 없음, [열기] 버튼이 H5만 여는지,
한국어/초성/병음/중국어 검색, 사진 저장 후 새로고침 유지, 요청사항 메모 조합·복사, 오프라인 새로고침,
카카오톡 인앱 안내를 확인한다. 테스트 중 외부 접속은 모두 막는다.

## 배포 (GitHub Pages)

1. GitHub 레포 → **Settings → Pages**
2. **Build and deployment → Source: Deploy from a branch**
3. **Branch: `main` / `/ (root)`** → Save
4. 1~2분 뒤 `https://lesumein.github.io/chifan/` 에서 열림 (빌드 단계 없음, `.nojekyll` 포함)

모든 경로가 상대경로라 `/chifan/` 하위 경로에서도 그대로 동작한다. HTTPS라서 클립보드·서비스워커도 동작한다.

**주의: github.io는 중국 본토에서 느리거나 불안정할 수 있다.** 그래서
- 처음 한 번 열 때 서비스워커가 앱 파일 전체(약 1MB, 대부분 단어장)를 캐시하고, 이후엔 캐시를 먼저 보여 준다(오프라인 가능).
- 가능하면 중국에 들어가기 전에 미리 열어 **홈 화면에 추가**해 두기.
- 중국에서 계속 안 열리면 다른 정적 호스팅(중국 접속이 되는 곳)을 다음 단계에서 검토.
